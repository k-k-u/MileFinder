# MileFinder

ANAマイルで交換できる特典航空券の**候補路線と必要マイル**を、条件からまとめて比較する日本語Webアプリです。ANA公式が公表したマイル表・シーズンを使い、国内108方向・国際43路線を収録しています。

**ローカル版で、ANA公式チャットの未ログイン時の空席回答を取得しました。** 照会ボタンからANAの応答取得・表示まで実動作を確認しています。必要マイルの候補一覧と、取得できた便別・日付別の空席回答を区別して表示します。国際線の直行便を対象とし、片道の回答表示に加え、往路・復路を個別照会した回答から往復候補を組み合わせます。

会員ログイン済みのANA予約画面と接続するブックマークレットも実装しました。国際往復・エコノミー・成人の検索結果から、公式が返した便の組み合わせ・席数・全員分の必要マイルと税金等を扱います。ローカル版の単日1名・2名照会で、要求・ANA応答取得・画面表示まで成功しました。会員の複数日連続取得は不安定です。ローカル版の匿名チャットでは複数日の実取得も確認しています。

公開用の構成は、Sites上の画面・Worker API・D1と、固定ANAアカウントへログインした管理PCのブラウザです。必要マイルの候補検索と匿名チャット照会を管理PCなしで利用する構成です。会員照会だけは管理PCと接続中のANAタブが必要です。管理PCが停止・スリープした場合やANAからログアウトした場合、会員照会を続けることはできません。

公開画面にANAの会員番号・パスワードを入力する機能はありません。会員照会の要求をクラウドへ送り、管理PCが順番に処理して、検証済みの便・日付・席数・全員合計料金だけを返す構成です。ANAのCookie・フォーム状態・応答HTMLはANAタブからクラウドへ送信しません。会員照会の対象は接続時の路線に固定され、接続の有効期間も制限します。

公開設定、管理PCの接続手順、保存データと運用上の制約は [DEPLOYMENT.md](DEPLOYMENT.md) を参照してください。以下の起動手順はローカル版です。

## 起動

Node.js 22.17.1以上の22系、または新しいLTS版を使用してください。

```powershell
npm ci
npm run dev
```

ブラウザで [http://127.0.0.1:5173/](http://127.0.0.1:5173/) を開きます。開発サーバーはローカルループバックで起動します。5173番ポートが使用中なら起動時にエラーになります。ローカル版の匿名チャットによる空席照会には、このNode.js側のサーバーが必要です。

## できること

- 国内線・国際線、出発空港、目的地の方面、最大62日間の出発期間で一括検索
- 東京（羽田・成田）のまとめ検索、全出発地の検索
- 片道／往復、復路出発日まで1〜30日、1〜9名、座席クラス、全員のマイル予算を指定
- 往路と復路のシーズンを別々に適用し、人数分の必要マイルを合算
- 路線一覧と日付別カレンダー、必要マイル順・目的地名順・候補日数順、方面別の絞り込み
- 検索条件と候補をブラウザの `localStorage` に保存
- 全日付別候補を日本語CSVで出力（UTF-8 BOM・数式対策付き）
- 検索実行後のURLを共有して同じ条件を再現
- 各路線のデータ出典と、ANA公式の空席照会案内を表示
- スマートフォン・タブレット・デスクトップ表示

匿名チャット連携では、候補の行き先を最大7日単位で順番に照会します。取得した便・日付・クラス・回答席数・確認時刻を表示し、希望人数を満たす回答の絞り込み、0席を含む表示、空席CSVに対応します。往復CSVには両便の現地出発日・便名・区間・席数・確認時刻、人数充足、合計必要マイルと部分取得の注記を含みます。

## 匿名チャットの空席照会

- 対象は収録済みの日本発国際線・ANA便名の直行便です。往復ではその逆方向も個別に照会します。各方向の出発日が本日から4〜355日後となる範囲を、最大7日ずつ照会します。
- 往復候補は、同じ具体的な空港の組み合わせを往復する回答から作ります。例えば羽田〜ホノルルの往路には、ホノルル〜羽田の復路を組み合わせます。両便とも希望人数以上の席数がある候補を初期表示し、残席不足・0席の組み合わせも切り替えて確認できます。復路日は海外出発地の現地出発日です。
- 会員ログインを使わない回答です。会員ステイタスによる優先枠は反映しません。人数はチャットへ指定せず、回答席数を取得後に希望人数で絞り込みます。
- 必要マイルは公開チャートからの計算値であり、空席回答から取得した価格ではありません。往復は各便の現地出発日に適用する往路・復路の片道マイルを合計し、人数分を計算します。税金・燃油サーチャージは含みません。
- チャットの続きの回答には翌日が混在するため、期間外の日付は除外します。ページ数に上限があり、結果は常に `partial` として扱います。表示されない便・日付・クラスを「空席なし」と判断しません。
- 片側の回答を取得できない場合、往復候補は未確認です。取得できた片側の回答を保持し、欠けている側を「空席なし」と扱いません。往復表示・CSVも部分取得として扱います。
- この接続では国内線の実空席、会員認証後の優先枠、往復旅程全体の予約可否を照会しません。個別の両便に空席回答があっても、その組み合わせを一つの往復旅程として予約できる保証はありません。取得後に空席が変わることもあるため、予約時はANA公式で再確認します。

## 会員予約画面との接続

1. MileFinderの「ANA会員の空席照会」を開き、「ANA会員検索を接続」をブラウザのブックマークバーへドラッグします。
2. ANA公式でログインし、国際線・往復・エコノミー・成人のみの検索でフライト一覧を表示します。
3. ANAのフライト一覧で保存したブックマークを実行します。新しく開いたMileFinderが、そのANAタブへ接続します。
4. 新しいMileFinderで日付・往復日数・人数・マイル予算を指定し、会員の空席を照会します。接続中はANAのタブを開いたままにします。

収録済みの日本発国際線が対象で、出発地・目的地は接続時の路線に固定します。別の路線はANA公式で検索し直して再接続してください。実装上は1回の操作で最大7出発日分を1件ずつ直列照会できますが、連続取得の安定動作は未確認です。成人1〜9名、エコノミーの予約クラス `X`、各方向1区間のANA便を扱い、乗り継ぎや他クラスは未対応です。日付は各空港の現地出発日です。

初回の照会条件が接続時の公式画面と完全に一致する場合は、表示済みの結果を1回だけ取り込み、重複したPOSTを避けます。確認時刻には接続時の取り込み時刻を保持し、新たに再検索した結果とは扱いません。別の日付・人数では会員検索へ照会します。

会員回答は、公式の往復組み合わせと指定人数分の合計料金です。必要マイル・税金等の円額を再乗算せず、予算と両便の席数で絞り込みます。東京全体で接続した場合は、公式が返した羽田発・成田着などの組み合わせも対象です。匿名チャットの個別便から作る候補とは区別して表示・CSV出力します。0席や空席待ちは空席ありに含めず、取得結果は部分取得・発券未確認として扱います。

会員番号・パスワード・Cookie・画面状態・応答HTML全文はANAタブ内だけで扱います。応答HTMLは画面へ追加せず、画像・iframe・CSSの追加読み込みやscript実行を防ぐ形で解析します。`postMessage` では区間・日付・席数・料金・確認時刻などの検証済み項目だけを渡し、送信先Origin・相手ウィンドウ・接続ごとのIDを双方で確認します。古いMileFinderウィンドウの通知で新しい接続を操作しません。ログイン切れ・画像認証・未知の応答・通信失敗を空席なしへ置き換えません。これらが発生した場合は公式画面で状態を確認し、接続し直してください。

## 空席連携の確認状況

以下はローカル版での確認記録です。ANA公式画面を実際に操作した通信調査は [ANA予約画面・公開チャットの実通信調査](docs/ANA_BROWSER_API_OBSERVATION.md) に記載しています。2026年9月23日00:01（日本時間）、MileFinderの実画面から2026年10月1日の東京〜ホノルルを照会し、NH186便・羽田21:55発・エコノミー2席を取得して表示しました。1名20,000マイルの表示は公開チャートによる計算です。取得結果は `partial: true` として扱います。

同日00:20には10月1〜2日の照会で、人数を満たす回答4件の取得・表示にも成功しました。途中の試行では回答待ちの時間切れも発生しており、常時取得や全件網羅を保証するものではありません。

国際往復もサイトから実照会し、10月1日成田→ホノルルのNH184（0席）と10月5日ホノルル→成田のNH183（0席）を取得しました。確認時刻は9月23日00:49・00:51（日本時間）。両便とも0席のため人数を満たす往復候補には数えず、0席表示をオンにした場合だけ、往復40,000マイルの計算値とともに表示することを確認しました。取得した部分回答の検証であり、全便の空席なしを示すものではありません。

追加調査で、ANA対応の掲載があるAwardWallet Flight Award Search APIとAwardTool Enterprise APIを候補に特定しました。[API調査結果](docs/AVAILABILITY_API_RESEARCH.md)と[問い合わせ下書き](docs/AVAILABILITY_API_INQUIRY.md)を参照してください。対応掲載の確認までで、認証した実照会と利用条件の確認は未実施です。

AMC番号やパスワードを受け取る画面はありません。候補の必要マイル計算はブラウザ内、匿名チャットの空席照会は公開版のWorkerまたはローカル版のNode.jsサーバー、会員照会は管理PCのログイン済みANAタブ内で行います。チャット接続用の設定・認証値はサーバー内で処理し、画面・ログ・リポジトリへ値を出力しません。Google Fontsからフォントを取得し、取得に失敗してもシステムフォントで動作します。
