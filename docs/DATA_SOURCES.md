# 特典航空券データの出典と収録範囲

確認日: 2026年9月22日。データ本体は `src/data/awards.ts`。

このサイトは、ANAの公開情報に基づいて必要マイル条件に合う路線を列挙する。候補一覧だけでは空席・運航日・提供クラスを確認していない。別途、ANA公開チャットの匿名空席回答を取得するローカル連携を実装し、2026年9月23日にMileFinderの画面から便別・クラス別の席数を取得して表示できることを確認した。会員連携でも同日02:29・02:30（日本時間）に、MileFinderからの単日の1名・2名照会で、往復旅程・席数・必要マイル・税金等の取得と画面表示に成功した。複数日の連続取得では時間切れも発生している。どちらも取得時点の部分回答であり、最終的な予約可否はANA公式で確認する。

## 計算範囲

- 国内線: 羽田・成田・伊丹・中部を中心とする直行54空港ペアを両方向に収録。ANA便名で購入する対象コードシェア便を含む。ANA全路線を網羅しない。
- 国際線: 日本出発の直行43路線。往復候補の空席連携では、その逆方向も個別に照会する。ANA国際線特典の日本発着チャートを使用し、提携航空会社特典とは区別する。
- 1人・片道のマイル数を保持する。往復は往路・復路それぞれの現地出発日のシーズンで計算して合算し、希望人数分の合計を求める。復路の日付は海外出発地の現地出発日であり、日本への到着日ではない。公式国際線チャートの東京〜ロサンゼルスの例も片道マイルの合算方法を示している。
- 国内線の搭乗クラスは普通席のみ。国際線はゾーン別料金表に存在するクラスを保持する。料金表にファーストクラスやプレミアムエコノミーの値があっても、各路線・各便がそのクラスを提供するとは限らない。
- マニラは地理的な表示分類を「東南アジア」とし、マイル計算ではANAのZone 3（アジア1）に分類する。地理分類で料金を計算しない。
- 国内線シーズンは2026年5月19日〜2028年3月31日、国際線は2026年1月1日〜2028年3月31日。期間外のシーズンやマイル数を推測しない。料金計算可能な期間と、予約受付・運航確認済みの期間は同義ではない。
- 年末年始・春節等のシーズン境界は年ごとに異なる。月日を他の年へ流用しない。国際線はアジア、欧米、ハワイ・オセアニアの3カレンダーを区別する。

## 静的データに収録しないもの

`src/data/awards.ts` は空席、空席待ち人数、便名、発着時刻、所要時間、機材、便別クラス設定、現金負担額、全世界の提携航空会社便、乗り継ぎ旅程、キャンペーン減額、小児・幼児に固有の計算を収録しない。空席連携で取得できた便名・日付・クラス・席数・出発時刻は、取得時刻を持つ別の回答として扱う。

成田〜台北桃園、関西〜香港、成田〜ニューヨーク等、参照した運航計画で休止中の路線を候補に追加しない。国際線は便数や運航曜日に例外があるため、路線の存在から希望日の運航を断定しない。掲載計画以降の運航継続も保証しない。

## 公開APIと空席照会

ユーザーの指示による公式画面の実通信調査は [ANA_BROWSER_API_OBSERVATION.md](ANA_BROWSER_API_OBSERVATION.md) に記録した。公式公開チャットとMileFinderの実画面で、匿名の東京〜ホノルルの便別・クラス別の席数回答を確認した。2026年9月23日には会員予約画面で画像認証後のフライト一覧に到達し、同区間の往復・エコノミー・成人の席数と料金を取得した。ANAタブ内のフォームPOSTでも検索結果HTMLと6組の旅程を取得した。国内線の実空席は未取得であり、他クラスや会員ステイタス間の在庫差は未確認。

第三者APIの追加調査は [AVAILABILITY_API_RESEARCH.md](AVAILABILITY_API_RESEARCH.md) に記載した。AwardWalletとAwardToolにANA対応の掲載を確認しており、試験アクセスと対象範囲・利用条件の確認が次の作業となる。

2026年9月22日にANAの公式サイトと公式サイトを対象とした検索を確認した範囲では、一般開発者向けの特典航空券空席API、その利用申請手順、公開仕様は見つからなかった。「APIが存在しない」と断定するものではない。公式の特典航空券ページは予約・空席照会に会員ログインを案内している。

### 匿名チャット

公開チャットで観測した通信を使うローカル接続を実装した。対象は収録済みの日本発国際線・ANA便名の直行便で、往復候補では往路と逆方向の復路を個別に照会する。各方向とも4〜355日後、最大7日単位の匿名回答を取得する。会員優先枠は反映せず、人数は取得した席数に対する絞り込みとして扱う。

往復候補は、同じ具体的な出発・到着空港の組み合わせを往復する便から作る。東京全体で検索した場合も、例えば羽田〜ホノルルの往路にはホノルル〜羽田の復路を対応させる。希望人数を満たす候補には両便で人数以上の席数が必要で、残席不足・0席の組み合わせも表示を切り替えて確認できる。必要マイルは空席回答の価格ではなく、公開チャートの往路・復路片道マイルを各現地出発日のシーズンで合算した計算値である。

各照会のページ送りは最大15ページで、続きには検索期間外の翌日が含まれる場合がある。期間外の回答を除外し、結果を常に `partial` とする。0席が明示された回答と、未取得・解析失敗・通信失敗を区別する。表示されない便やクラスの空席は未確認のままとする。片側が未取得の往復は候補が未確認であり、その側を空席なしと判断しない。取得できた回答は保持する。

往復CSVは両便の現地出発日・便名・区間・席数・確認時刻、希望人数、両便の人数充足、合計必要マイルを含む。往復表示・CSVとも部分取得であり、個別空席から組み合わせた候補を示す。この匿名接続は、会員認証後の優先枠や往復旅程全体の予約可否の回答ではない。

チャット接続の設定・認証値はNode.js側で処理し、値を画面・ログ・リポジトリへ出力しない。匿名空席APIはローカルのdev/previewサーバー専用で、静的な `dist/` のみでは動作しない。

### 会員予約画面

会員連携は、ユーザーがログインしてフライト一覧を表示したANAタブでブックマークレットを実行し、新しく開くローカルMileFinderから照会する。接続時の日本発国際線の出発地・目的地を固定し、往復・エコノミー・成人1〜9名に限定する。1回の操作で最大7出発日分を、日付ごとの往復検索として直列に送る実装だが、連続取得の安定性は未確認。各方向1区間のANA便・予約クラス `X` だけを解析し、乗り継ぎを直行便へ短縮したり他クラスの対応を推測したりしない。

接続時に公式画面の表示済み結果を解析し、初回照会の区間・往復日付・クラス・人数が完全に一致した場合は、そのスナップショットを1回だけ返す。取り込み時の確認時刻を保持して重複POSTを避け、新しい空席を再照会した結果とは扱わない。条件が一致しない場合や後続の照会ではフォームPOSTを使う。

9月23日03:03（日本時間）には、公式画面に表示中の10月4日往路・10月7日復路・TYO〜HNL・エコノミー1名の結果をこの経路で6組取り込んだ。必要マイル40,000、税金等は羽田発90,250円・成田発90,460円。往路NH186は6席・NH184は9席、復路は0席だった。追加のAPI POSTを行った取得ではなく、既存画面からの読み取り成功である。

会員応答の `addRecommendation` と区間情報から、公式が返した往復旅程・席数・必要マイル・税金等の円額を読み取る。料金は指定人数分の合計で、静的チャートによる再計算や人数の再乗算をしない。MileFinderの実照会では、10月2日往路・10月5日復路・TYO〜HNL・エコノミーで1名40,000マイル、2名80,000マイルを確認した。税金等は1名が羽田発90,250円・成田発90,460円、2名が羽田発180,500円・成田発180,920円で、いずれも全員合計。各照会は6組を返した。1名照会の往路NH186は6席・NH182は9席・NH184は0席、復路NH183・NH185はともに0席だった。東京全体（TYO）では、公式の組み合わせに含まれる羽田発・成田着も条件一致となる。往路と復路の日付はそれぞれの現地出発日を照合する。

10月2〜3日の2日分を連続照会した試験では、1日目は取得できたが、2日目は60秒で時間切れとなった。別の試行では結果GETが約62.6秒後に `ERR_EMPTY_RESPONSE` で失敗し、待機延長のみでは解消しなかった。公式カレンダーで10月4日往路・10月7日復路を選択し直したTYO〜HNL・エコノミー1名のフォームからは、約4.6秒・HTTP 200で6組を取得した。成功する単日検索がある一方、会員の複数日連続取得は不安定という制約を持つ。取得済みの結果を保持し、未取得日は空席なしとしない。複数日は実取得を確認した匿名チャット照会も利用できるが、会員回答との在庫の一致や全件網羅は保証しない。

0席・人数不足を保持し、空席待ちは空席ありに含めない。取得できない条件・未知書式・認証切れ・画像認証・通信失敗は未確認として扱い、空席なしへ変換しない。結果は常に `partial: true` とし、会員CSVには両方向の便・日付・区間・席数、成人数、全員分のマイル・税金等、確認時刻、部分取得・発券未確認の注記を含める。CSV内容は外部通信を模擬したE2Eで検証済みだが、実会員照会からのブラウザダウンロード操作は未確認。会員画面に検索結果があることと、即時発券できることは区別する。

AMC番号やパスワードを受け取る画面はない。認証・Cookie・画面状態・応答HTML全文はANAタブ内に保ち、観測済みのliteralを解析して表示用の項目だけを取り出す。応答HTMLはライブ画面へ挿入せず `template.content` で扱い、画像・iframe・CSSの追加通信や外部応答のscript実行を防ぐ。フォームPOST後の同一Originへの302と結果GETに追従し、別Originへのリダイレクトは拒否する。`postMessage` の送信先Origin・送信元ウィンドウ・接続ごとのUUIDを確認し、古いウィンドウの通知を拒否する。MileFinder側でも区間・日付・クラス・席数・料金を検証する。会員接続と匿名チャットは別の取得元として扱う。

応答HTMLでは空のままになり、公式画面のJavaScriptが補完していた空港表示名を、接続時のライブフォームから保持して各POSTへ補完する。成人のみの条件に合わせて `hiddenDomesticChildAge` を `false` とし、`URLSearchParams` が設定するUTF-8のフォーム送信を使う。これらと安全なHTML解析の改善は、会員の連続取得が安定したことを示すものではない。

## 更新方法

1. 公式チャートの適用開始日と片道／往復のタブを確認し、`PRICING` を更新する。国際線ページには改定前の往復値も残っているため混用しない。
2. シーズンの公表期間を確認し、`SEASON_CALENDARS` を更新する。両端を含む日付として扱い、重複・欠落を検査する。
3. 最新の公式運航計画と国内時刻表で発着空港を照合し、`ROUTES` と出典URLを更新する。便の一部休止と路線全体休止を区別する。
4. `DATA_UPDATED_AT` とこの文書の確認日・収録件数を更新する。検索テストとデータ参照整合性の検証を実施する。

ANAの説明本文・表の見た目・画像を複製せず、路線、日付、必要マイルという事実データを検索向けに構造化している。ANAの公式サイトではなく、ANAとの提携・公認を示すものではない。
